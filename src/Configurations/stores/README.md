# Хранилища и миграции

В `bootstrap.yaml` хранится только **перечисление** хранилищ:

```yaml
stores:
  items:
    - accounts
    - fetch_api
    - game
    - messages
    - system_router
```

Настройки каждого хранилища лежат в отдельном файле
`stores/<имя>.yaml` рядом с `bootstrap.yaml`. Имя из списка нормализуется к
нижнему регистру; файл называется так же (`fetch_api` → `stores/fetch_api.yaml`).
Хранилище, имя которого есть в списке, но файла нет, — ошибка запуска.

Чтобы отключить хранилище, уберите (или закомментируйте) его имя в
`stores.items`. Файл настроек и SQL-миграции при этом остаются на месте:
вернуть хранилище — значит снова добавить имя в список. Файлы `stores/<имя>.yaml`,
которых нет в списке, не читаются.

Отключение убирает контекст `.store.<имя>` и его настройки/миграции. Модуль,
который обращается к алиасу напрямую через `DatabasesService::connection()`,
при этом откроет базу по умолчанию `data/<имя>.db` без этих настроек.

## Файл настроек

Пример `stores/fetch_api.yaml`:

```yaml
name: fetch_api          # необязательно; если указано, совпадает с именем файла
path: data/fetch_api.db  # необязательно; по умолчанию data/<имя>.db в профиле
encrypted: false         # SQLCipher; ключ задаётся во время входа пользователя
wal:
  checkInterval: 60000   # мс между проверками размера WAL
  maxSizeMb: 40          # порог авто-чекпоинта
migrations:
  - version: 20251113181900
    description: Initialize database
    up: stores/migrations/fetch_api/20251113181900-up-Initialize-database.sql
    down: stores/migrations/fetch_api/20251113181900-down.sql
```

Пустой файл (или файл только с комментариями) — хранилище со значениями по
умолчанию: путь `data/<имя>.db` в профиле, без шифрования, WAL 60000 мс / 20 МБ.

`path` задаётся относительно каталога профиля или абсолютным путём. Остальные
поля необязательны.

## Миграции

Пути SQL-файлов разрешаются относительно каталога `bootstrap.yaml`. Версия —
дата и время в формате `yyyyMMddHHmmss`; имена файлов обязаны содержать ту же
версию и направление. Описание после `-up` необязательно. Указываются оба
файла, а миграции применяются по возрастанию версии, независимо от порядка в
YAML. Файлы, не перечисленные в настройках, не загружаются.

Ранее зарегистрированные в коде миграции и их версии больше не поддерживаются.
Рабочая копия конфигурации в профиле должна содержать перечисленные SQL-файлы.

## Резервные копии

Копии файлов баз создаёт документ «Резервное копирование баз данных»
(`database-backup`, модуль `DatabaseModule`). Копии лежат в профиле:

```text
backups/<имя хранилища>/<yyyyMMdd-HHmmss-zzz>.db
```

Копируется файл базы как есть (для `encrypted: true` — зашифрованный файл).
Перед копированием WAL сворачивается, поэтому снимок состоятелен; перед
восстановлением создаётся страховочная копия `*-before-restore.db`. Подробнее —
`docs/database-backup/README.md`.
