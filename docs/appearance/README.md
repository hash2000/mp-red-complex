# Внешний вид на разных компьютерах

Документ объясняет, почему приложение могло выглядеть по-разному на двух
машинах с одинаковой сборкой, и какие правила действуют теперь.

## Почему раньше вид отличался

1. **Qt-стиль не был зафиксирован.** По умолчанию на Windows используется
   `windows11` или `windowsvista`: эти стили рисуют кнопки, вкладки и рамки по
   системной теме Windows (светлая/тёмная тема, версия ОС, высокий контраст).
   Поэтому одинаковые QSS и палитра давали разный результат на разных машинах.
2. **Палитра задавала не все роли `QPalette`.** Для ролей, которых нет в
   `palette.yaml` (например, `Button`, `AlternateBase`), оставался светлый
   системный цвет. Из-за этого «системно-нарисованные» кнопки и вкладки
   становились белыми.
3. **В QSS не было общих правил для `QToolButton` и `QTabWidget`.** Эти
   элементы без собственного `objectName` рисовал системный стиль: отсюда и
   белый цвет, и другие размеры (у стилей разные отступы и метрики).
4. **Шрифт не задавался явно.** Системная настройка «Размер текста» и
   подстановка другого шрифта меняют метрики текста, а вместе с ними — размеры
   кнопок и отступы.
5. **Тема читается из профиля, а профиль — рабочая копия.** Если профиль был
   создан более старой сборкой, в нём лежат старые `stylesheets`/`palette.yaml`,
   и приложение выглядит по-старому, даже если бинарник новый.

## Что сделано в коде

- `Application::setupAppearance()` (`src/Libs/Engine/application.cpp`) —
  принудительно включает стиль **Fusion** и задаёт шрифт **Segoe UI 9pt**.
  Fusion рисует только по палитре и QSS темы, поэтому вид не зависит от версии
  Windows и её темы оформления.
- `assets/themes/dark/palette.yaml` — палитра заполнена полностью: `Button`,
  `AlternateBase`, `Light`/`Midlight`/`Mid`/`Dark`/`Shadow`, `BrightText`,
  `HighlightedText`, `Link`, `PlaceholderText`, `ToolTipBase`/`ToolTipText`.
- `assets/themes/dark/stylesheets/base.qss` — общие правила для `QToolButton`,
  `QTabWidget`/`QTabBar` и `QGroupBox`. Специализированные кнопки с собственным
  `objectName` по-прежнему переопределяют их.
- В лог при старте пишется строка для сравнения машин:

  ```text
  Appearance: style=fusion font=Segoe UI size=9 dpr=1 scaleFactor=
  Stylesheet applied: 18342 bytes
  Palette applied: window #323232 base #232323 button #313131 text #cfcfcf
  ```

## Как проверить и починить конкретную машину

1. Сравните строки `Appearance:`/`Palette applied:` в логах обеих машин —
   они должны совпадать (кроме `dpr`, если у мониторов разный масштаб).
2. Если тема выглядит по-старому, обновите рабочую копию конфигурации из
   сборки:

   ```text
   RedComplex.cmd /update-config
   ```

3. Проверьте масштаб Windows (Параметры → Дисплей → Масштаб). При 125/150%
   все элементы физически крупнее — это ожидаемо; `dpr` в логе показывает
   фактический коэффициент.
4. Убедитесь, что в распакованном архиве есть каталоги плагинов
   `platforms`, `imageformats`, `tls`. Плагин `styles` больше не обязателен:
   Fusion встроен в Qt, но он всё равно кладётся в пакет.

## Правила для новых виджетов

- Внешний вид задаётся только темой: `setObjectName()` в коде и правило в
  `.qss`. `setStyleSheet()` в модулях и `Libs` не используется.
- Не полагайтесь на то, что элемент «как-нибудь» нарисует системный стиль:
  цвета, рамки, радиусы и отступы должны быть в QSS.
- Размеры кнопок — через `min-width`/`min-height`/`padding` в QSS, а не через
  `fontMetrics()` и пиксельные константы в коде.
- Шрифты — явно: `font-family`/`font-size` в QSS или `QApplication::setFont()`.
  Для моноширинных используйте `Consolas` с запасным `Courier New`.
- Динамические состояния — через `setProperty()` + `style()->unpolish/polish`,
  как это уже сделано для `state` в fetch-api.

## Ограничения

- При разном DPI физические размеры элементов отличаются — это нормальное
  масштабирование интерфейса, а не расхождение темы.
- Шрифт фиксирован, поэтому системная настройка «Размер текста» на приложение
  не влияет.
- Эмодзи-глифы рисуются системным шрифтом (`Segoe UI Emoji`); если нужна
  абсолютная идентичность, используйте иконки из ресурсов, а не символы.
