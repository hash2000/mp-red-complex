# Виртуальный редактор больших файлов

`PagedTextEditor` открывает файлы, которые нельзя прочитать в память целиком:
в памяти живёт только индекс начал строк и несколько страниц по 2000 строк.
Документ-обёртка — `PagedTextDocument` (xtype `text-editor`,
переменная контекста `path`).

## Глобальные параметры текста

Значения по умолчанию оба текстовых документа (`CodeEditorDocument` и
`PagedTextDocument`) берут при создании из системных параметров
(`SystemOptionsRegistry`, переменные глобального контекста):

| Параметр | Значение |
|---|---|
| `documents.text.buffer.limit` | предел буфера виртуального редактора, МБ; `0` — без предела |
| `documents.text.wordwrap` | перенос длинных строк |
| `documents.text.font.size` | размер шрифта в пунктах; `0` — системный |
| `documents.text.font.family` | семейство шрифта; пустая строка — системный моноширинный |
| `documents.text.encoding` | кодировка чтения и записи (имя кодека `QTextCodec`) |
| `documents.text.tab.spaces` | ширина отступа и табуляции в символах (Prettier `tabWidth`, по умолчанию 2) |
| `documents.text.tab.edit` | что вставляет Tab: `spaces` (Prettier `useTabs=false`) или `tabs` |
| `documents.text.tab.save` | как сохранять ведущие табы: `spaces` или `tabs` |
| `documents.text.navigation` | стратегия `Ctrl+Left/Right` из `TextNavigationStrategyRegistry` (по умолчанию `words`) |

Параметры меняются в документе системных настроек (⚙) и применяются к новым
документам: `onContextAttached()` читает их через свой контекст (значения
наследуются из глобального) до открытия файла. Документ может изменить
параметр у себя, не затрагивая глобальный. `wordwrap=false` выключает
автоперенос у редактора кода; в свойствах документа по-прежнему можно
выбрать `Auto`/`On`/`Off` вручную.

## Модель памяти

- `PagedFileIndexer` в фоновом потоке считает смещения начал строк; строки
  на диск не читаются.
- `PagedDocumentBuffer` — модель текста. Файл разбит на страницы по
  `PagedDocumentBuffer::kPageLines` (2000) исходных строк.
- Изменённая страница загружается в память и остаётся в ней отдельным
  списком строк: это и есть карта «страница → изменённый буфер».
  Неизменённые страницы по-прежнему читаются с диска и вытесняются из кэша.
- Память растёт вместе с объёмом правок, а не с размером файла.
  `PagedTextEditor::modifiedPageCount()` показывает, сколько страниц изменено,
  `isModified()` — есть ли несохранённые правки.

## Документ без файла

`PagedTextEditor` создаётся с пустым документом («Без имени»), а не с пустым
просмотрщиком: сразу доступны ввод, вставка, отмена и сохранение.
`PagedTextDocument` без переменной `path` ведёт себя так же. Содержимое
такого документа — это целиком изменённые страницы; `save()` спросит путь и
запишет их обычным образом. Поэтому документ без файла можно открыть
Командой `documents action=create, target=text-editor` и начать печатать.

## Предел буфера и файл подкачки

- `PagedTextEditor::setMemoryBudget(bytes)` задаёт, сколько памяти отводится
  под изменённые страницы; по умолчанию `32 МиБ`, `0` — без предела.
  В свойствах документа это поле «Предел буфера».
- Когда предел превышен, `PagedDocumentBuffer` выгружает страницы в файл
  подкачки и читает их оттуда при следующем обращении. Выгруженная страница
  остаётся изменённой: сохранение возьмёт её из файла подкачки, а отмена
  восстановит снимок из него.
- `bufferedBytes()` — сколько памяти занято сейчас, `spilledPageCount()` —
  сколько страниц имеет запись в файле подкачки, `spillFilePath()` — путь
  этого файла.
- Файл подкачки — `QTemporaryFile` в `QDir::tempPath()` с
  `setAutoRemove(true)`: он удаляется при уничтожении модели (закрытие
  документа, сохранение, выход). Это стандартный механизм Qt, без
  привязки к ОС. Если приложение аварийно завершится, файл останется в
  системном каталоге временных файлов и будет убран его штатной очисткой.
- В файле подкачки данные лежат в открытом виде (как и в самом документе),
  поэтому он создаётся только при реальном превышении предела.
- Текущая страница может остаться в памяти сверх предела: её текст нужен для
  отрисовки и правки. При обращении к другой странице она выгружается.
- Файл подкачки только дописывается: записи старых версий страниц
  освобождаются вместе с файлом (при закрытии, сохранении или перечитывании
  документа), поэтому он может быть больше текущего объёма правок, но живёт
  не дольше документа.

## Редактирование

- Ввод текста, `Enter`, `Tab`, `Backspace`, `Delete`; ввод через IME
  (`inputMethodEvent`).
- Вставка из буфера обмена (`Ctrl+V`, кнопка ленты, контекстное меню),
  вырезание (`Ctrl+X`), копирование (`Ctrl+C`), выделение (`Ctrl+A`,
  мышью, с `Shift`).
- `Ctrl+Z` / `Ctrl+Y` — отмена и повтор.
- `PagedTextEditor::setReadOnly(true)` запрещает правки, оставляя навигацию
  и копирование.
- `Tab` вставляет отступ по `documents.text.tab.edit`: `spaces` — столько
  пробелов, сколько задано в `documents.text.tab.spaces`, `tabs` — `\t`.
  Ширина отображения табуляции тоже берётся из `tab.spaces`.
- При сохранении ведущие табы каждой строки заменяются пробелами, если
  `documents.text.tab.save = spaces`; `tabs` оставляет их как есть.
- `Ctrl+Left/Right` — переход по токенам. Стратегия подставляется
  (`PagedTextEditor::setNavigationStrategy`) и по умолчанию берётся из
  `documents.text.navigation`; базовая стратегия `words` идёт до первого
  символа другого класса (буква/цифра против пробела, табуляции, пунктуации).
- `Ctrl+Backspace/Delete` удаляют по тому же токену: слева/справа от курсора,
  а на границе строки — перевод строки. Выделение удаляется целиком.
- `Ctrl+Up/Down` прокручивает экран на строку, не перемещая курсор;
  `Ctrl+Enter` вставляет строку выше текущей и оставляет курсор в своей строке.
- `Tab` не уводит фокус на следующий виджет, а вставляет отступ.
- Клик ниже последней строки ставит курсор в её конец; над текстом показан
  курсор ввода (I-beam).

Правка загружает только затронутые страницы. Если диапазон пересекает
границу страниц, страницы между его началом и концом опустошаются без
чтения с диска — поэтому удаление тысяч строк не приводит к чтению файла.

## Многокурсорность

- `Alt`+клик добавляет или убирает курсор; на строке — не больше одного
  курсора. `PagedTextEditor::cursorCount()`/`cursorPositions()` показывают
  набор, `addCursorAt()` добавляет курсор программно.
- `Shift+Alt` + мышь (от нажатия до отпускания) или стрелки/`Home`/`End`/
  `PageUp`/`PageDown` выделяют прямоугольную область от верхнего курсора
  (при нескольких курсорах — от самого верхнего по тексту) до активной
  точки. Область разворачивается в отдельное выделение на каждой строке;
  строки, в которые не попал ни один символ диапазона колонок, курсор не
  получают (например, пустые и слишком короткие).
- `Ctrl+D` дублирует строку ниже (у каждого курсора — свою; курсор остаётся
  на копии).
- `Ctrl+C`/`Ctrl+X` без выделения работают со строкой целиком: копируют её
  текст, а вырезание удаляет строку (у последней строки — вместе с
  предшествующим переводом строки).
- Вставка (`Ctrl+V`) распределяет строки буфера по курсорам в текстовом
  порядке: один курсор — весь текст как есть; курсоров меньше, чем строк, —
  первые строки, лишние не вставляются; курсоров больше — строки идут по
  кругу.
- Ввод, `Backspace`/`Delete`, `Ctrl+D` и замена выделения применяются ко
  всем курсорам одной правкой; одна отмена возвращает и текст, и набор
  курсоров.

## Подсветка

`PagedTextHighlighter` применяет те же правила плагинов темы, что и
`Highlighter` редактора кода, включая вложенные блоки (например, `script` и
`style` в HTML и ` ``` ` в Markdown). Форматы `start`/`end` применяются даже
без вложенного языка: так подсвечиваются многострочные открывающие теги и
закрывающие теги, а строки внутри обрабатываются правилами базового языка
(атрибуты HTML). Если язык вложенного блока задан, его содержимое
подсвечивается плагином этого языка. Состояние «внутри блока» считается
лениво по запросу строки и кэшируется контрольными точками, поэтому подсветка
одного и того же текста в code-editor и text-edit совпадает. Форматы правил
(в том числе `pointSize`) участвуют в расчёте геометрии строк — клик мышью
попадает в правильную строку и колонку при разных размерах шрифта.

## История правок

`PagedEditHistory` хранит снимки только затронутых страниц:

- чистая страница в снимке не хранит текст — при отмене она снова читается
  из файла, поэтому отмена удаления тысяч страниц стоит несколько байт на
  страницу;
- изменённая страница сохраняется списком строк (QString разделяются между
  снимками, правка всегда создаёт новую строку целиком);
- подряд идущие односимвольные вставки и посимвольное удаление склеиваются
  в один шаг отмены, если набор страниц и позиция курсора не менялись;
- история ограничена `kMaxRecords` записями и `kMaxCost` байтами: старые
  записи удаляются.

Выгрузка страниц в файл подкачки не мешает отмене: если снимку нужен текст
выгруженной страницы, он читается из файла подкачки в момент создания
снимка.

## Сохранение

`PagedTextEditor::save()` пишет в текущий файл, `saveAs()` — в указанный
(после записи документ продолжает работать с ним). Запись идёт через
`QSaveFile`:

- изменённые страницы кодируются текущей кодировкой и разделяются тем
  переводом строки, который был в файле (`\r\n` или `\n`);
- неизменённые страницы копируются с диска байт в байт, BOM сохраняется;
- после записи файл переиндексируется в фоне, курсор и прокрутка
  восстанавливаются.

Пока есть несохранённые правки, перечитывание файла, смена кодировки и
форматирование отказывают — иначе правки потерялись бы.

## Поиск

`runPagedLineSearch` получает снимок буфера: изменённые страницы берутся из
памяти, неизменённые читаются с диска, поэтому поиск учитывает
несохранённые правки и не блокирует GUI. После правки поиск перезапускается
с задержкой и не переводит курсор на найденное.

## Ограничения

- Поддержаны UTF-8 и однобайтовые кодировки (`QTextCodec`); UTF-16/UTF-32
  не поддержаны.
- Состояние вложенных блоков при прыжке в неизвестное место пересчитывается
  не дальше чем на 20 000 строк назад: на очень больших Markdown-файлах
  подсветка внутри давно открытого блока может начаться не с первой строки.
- Очень длинные строки показываются кусками по 2000 символов
  (`PagedLineChunks`): остаток догружается горизонтальной прокруткой, а
  правка в незагруженном куске возможна, но курсор там не виден.
- `maxLineLength()` после правок — верхняя оценка: полный пересчёт
  потребовал бы чтения всех страниц.
- Отмена правки после сохранения недоступна: сохранение перестраивает
  индекс строк.
- Предел памяти считается по изменённым страницам; снимки истории
  ограничены отдельно (`PagedEditHistory::kMaxCost`), поэтому общий объём
  памяти складывается из этих двух пределов.
